# Codex 执行约定

第一次操作 Blender、调用本包脚本或处理中断恢复时读取。执行入口与依赖检查见[脚本说明](../scripts.md)。

## 依赖与安装确认

优先使用机器上已有的 Blender、Python 环境和 MCP 连接。预检发现 Blender 或当前步骤必需的 Python 包缺失时，向用户列出缺失项、受影响的步骤及拟采用的安装方式和位置，询问是否安装；获得本次会话中对这些安装项的明确同意后再执行。已有同意继续有效，安装范围增加时补充确认。

等待答复期间可继续照片分析和清单整理。用户暂缓或拒绝安装时，保存已有工作并说明依赖哪些安装项才能继续。可选图像诊断工具的依赖在启用该工具时处理。版本查询或 MCP 连接失败时先核实路径和连接状态，确认确实缺少软件后再提出安装。

安装完成后复查涉及的依赖，并用只读场景查询确认 MCP 可用，再继续对应制作步骤。

## 连接与现有场景

通过当前工具描述发现 Blender 的场景读取、对象读取、图像捕获和代码执行能力，按实际命名空间调用。首次写入前读取场景和范围内对象，并查看基准图像。使用预检得到的 Blender 版本、可执行文件和可用功能。

已存在的场景以当前对象为基础迭代。新建构造内容放入本次工作集合，保存广泛修改前的检查点。当前用户授权与主[制作流程](../workflow.md)决定可以修改的范围。

## 代码执行

每次 Blender 代码调用独立导入所需模块，通过稳定名称和清单身份重新查找持久对象。按一个明确目的组织调用，并返回紧凑的对象、尺寸或状态证据。

优先使用 data API 或 `bmesh` 表达可确定的编辑；`bpy.ops` 调用显式设置模式、选中范围和活动对象。根据实际 bpy 属性及节点插槽编写版本相关操作。

错误或超时后先读取场景当前状态，确认该次操作实际完成到哪一步，再恢复受影响阶段。源脚本与场景中的稳定身份用于更新已有结果，完成后核对重复对象和范围外影响。

## 文档与脚本路径

本目录文件是本包的参考模块，按主入口条件读取。文件内相对链接以当前文件位置解析；运行脚本时从安装的本包目录得到脚本绝对路径，并传入明确的输入和持久输出路径。

Python 依赖使用预检确认的环境；Blender 内部脚本通过对应 Blender 可执行文件运行。本包脚本能力与 CLI 以[脚本说明](../scripts.md)和实际 `--help` 为准。

## 图像与结果

实际查看用户提供的图像、保存的照片比对图和所需单件证据。生成成功、文件存在与视觉检查分别记录。交付文件经存在性、内容与回读核对后，使用绝对路径链接源文件、模型与预览。
