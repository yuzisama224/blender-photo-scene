# 场景装配与对象身份

新增物件、布置场景、处理实例或整理交付对象时读取。对象与清单的对应规则以[物件清单](../manifest.md)为准。

## 场景组织

按[清单](../manifest.md)定义的独立任务场景组织内容，再用集合分类交付几何、图像参考、灯光和相机。清单身份绑定到交付 MESH 对象，构造资料的保存范围遵循清单约定。物件的位置、角度、遮挡顺序和表面接触以照片为依据。

相同造型可用共享网格 data 的不同对象，每个对象保留独立位置、旋转、原点和清单身份。单件形状需要独立修改时再复制网格 data；材质变化按对应材质用户范围处理。

## 单件交付整理

清单每件物品对应一个 MESH。该网格允许包含多个面岛和多个材质槽。将一个物件的零件合并时：

1. 只选取属于该物件的构造零件，保留合并前检查点。
2. 求值需要固化的曲线、实例和修改器，并将零件坐标转换到目标对象空间。
3. 合并为单一网格，保留各面的材质分配、UV、需要的着色和面岛。
4. 设置整体移动原点与稳定身份，核对世界位置和外部尺寸。
5. 用清单及[脚本](../scripts.md)核对最终对象集合，并检查导出回读后的对应关系。

`Realize Instances` 产生的几何仍需按物件身份拆成独立对象；分离面岛的数量与真实物品数量分别判断。父级、约束或驱动产生的依赖关系按清单交付要求整理，确保单件变换影响范围正确。

## 移动与接触

整理时核对物件接触与可选状态，有约束、父级或异常依赖的物件按需试移；全量平移、旋转和还原由导出时验证集中执行，见[验收](qa.md)。地面、台面等支撑与物件底部接触合理；薄部件间的微小偏移按实际尺度处理，确保没有共面闪烁。

可移动物件的侧、背、底和被移开后暴露的支撑面按观察范围补齐。原照片位置与验证用临时变换分别保存，最终交付恢复照片布局。证据和判定见[验收](qa.md)。
