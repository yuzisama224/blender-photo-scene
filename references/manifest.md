# 物品清单

每个任务维护一份 `scene-manifest.json`。这是物品身份与交付对象的唯一对应表。清单中的物品由照片与用户需求确定，厨房等例子只是其中一种场景。

```json
{
  "schema_version": 1,
  "reference_image": "参考照片.jpg",
  "photo_camera": "照片视角",
  "items": [
    {
      "id": "item-001",
      "name": "陶瓷杯",
      "object": "陶瓷杯",
      "movable": true,
      "reference_region": [0.25, 0.40, 0.36, 0.61],
      "dimensions_basis": "高度按台面比例推估为 0.10 m；背面按旋转对称结构补齐",
      "source": {"type": "modeled"}
    }
  ]
}
```

## 字段与身份

- `reference_image`：相对清单的照片路径或绝对路径。`photo_camera`：作者工程中的照片匹配相机名称。
- `id`：任务内唯一且稳定的标识；`name`：用户能识别的物品名称；`object`：作者工程中的唯一 Blender 对象名称。
- `movable`：严格的布尔值。移动单位是现实中的完整物品。固定结构同样登记为 `false`，重复物品每件单独登记。
- `reference_region`：照片中的归一化矩形 `[左, 上, 右, 下]`，范围 0–1，左小于右、上小于下。需要补齐的隐藏部分使用所属物品区域，在 `dimensions_basis` 中说明推估。
- `dimensions_basis`：尺寸依据、单位和必要的隐藏结构假设。用户实测优先，其次为可核查规格，再次为比例推估。模型采用米。
- `source.type`：`modeled` 或 `public_asset`。公开素材另填非空 `url`、`license`、`attribution`，记录具体作品地址、许可和署名；CC0 也记录提供者。

每个已登记对象写入 `obj["photo_scene_id"] = item["id"]`。作者工程同时检查对象名称和 ID；GLB 导入后按 ID 对应，以允许导入器重命名。任务使用独立的 Blender Scene，保存时将它设为活动场景；清单完整登记这个场景中的所有网格。相机、灯光和组织用空物体属于该场景的制作辅助。构造备份及其他已有模型保存在别的 Scene 或阶段工程文件，验证和导出范围均为已保存的活动任务场景。

## 整件物品

一件小物品交付为一个 `MESH` 对象。杯把、瓶盖、贴花几何等在该对象内保留网格岛和材质分区；每个对象的原点放在适合摆放和旋转的位置。原始构建脚本保留分件制作过程。

使用外部模型时先核对实际许可证，再按清单统一尺度、朝向、材质和对象身份。需要合并曲线、文本或多个零件时，先在当前任务副本中求值为网格，再合并为物品对象。几何节点实例在交付求值结果中具有完整形体；共享网格数据允许保留独立对象变换。

交付物品应在对象模式可见、可选，位置和旋转能独立改变。检查脚本会比较依赖图求值后的形体，识别移动被约束抵消或牵连其他对象的情况。

## 其他任务记录

将照片中的可见结构、遮挡关系、透视判断和当前阶段的视觉检查写在任务的场景说明中。贴图、HDRI 等全局素材写入同目录的素材清单，记录 URL、许可证、署名和使用位置；物品的外部模型来源仍由这里的 `source` 负责。

脚本报告通过 `id` 对应清单，字段及调用见 [工具入口](scripts.md)。
